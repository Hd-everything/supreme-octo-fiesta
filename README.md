# Status HD

A Flutter app for preparing photos and videos for WhatsApp Status, with a premium dark interface and device-local appearance customization.

## Current features

- Cross-platform Flutter/Dart codebase for Android and iOS.
- Select a photo or video through the system media picker.
- Preview selected images and play/pause video previews.
- Trim a selected video range and split it into clips up to 30 seconds.
- Native Android MP4 remuxing and iOS AVFoundation passthrough export, where the source format supports it.
- Share the selected original file through the system share sheet without intentionally re-encoding it.
- Custom accent colors, AMOLED black mode, compact layout, and rounded/sharper surfaces.
- Appearance settings persist locally on the device.
- No account or media-upload backend is required for the core workflow.
- GitHub Actions builds a signed Android release APK on each push to `main`.

## Build locally

Install Flutter stable and the platform toolchain, then run:

```sh
flutter create --platforms=android,ios --org com.ptip --project-name statushd --overwrite .
flutter pub get
flutter analyze
flutter test
flutter run
```

The application ID generated by this organization/project name is `com.ptip.statushd`, separate from Fasmora's `com.ptip.pulse`.

## GitHub Actions artifacts

Open the repository's **Actions** tab, select **Build Status HD**, and download `statushd-android-release` after the Android job succeeds.

The workflow signs the release APK with a keystore stored only in GitHub Actions repository secrets. Configure these secrets before triggering it:

- `KEYSTORE_BASE64`: Base64-encoded contents of the release `.jks` or `.keystore` file.
- `KEYSTORE_PASSWORD`: Keystore password.
- `KEY_ALIAS`: Signing-key alias.
- `KEY_PASSWORD`: Signing-key password.

For example, create the first value locally with `base64 -w 0 release.keystore` on GNU/Linux, or `[Convert]::ToBase64String([IO.File]::ReadAllBytes('release.keystore'))` in PowerShell. Never commit the keystore or its passwords.

## iOS distribution

Building an iOS simulator app does not require App Store signing. To distribute an iOS app to a physical iPhone or the App Store, configure Apple signing and provisioning through a macOS/Xcode workflow. Never commit Apple certificates, provisioning profiles, keystores, or passwords to this repository.

## Video trimming note

Video segment export aims to avoid re-encoding where the platform/source permits. Lossless boundaries can align to nearby keyframes, and some source formats may fail to export. Original files are not overwritten. Temporary exported clips are stored in the app's temporary directory.

## Video processing and quality

On Android, Status HD processes the selected source video locally with AndroidX Media3 Transformer. The enhancement pass applies brightness, contrast, saturation/lightness, high-quality Lanczos resampling, and H.264/AAC re-encoding at the selected output dimensions. Status HD and Movie Player remain separate features; the player can create its own enhanced copy using the same local processing channel. The app verifies that a non-empty processed file was created, offers an in-app playback preview, and then lets the user save or share that processed copy.

The source file is not overwritten; the processed result is a separate copy. Increasing dimensions alone cannot recover details that were never captured, and these filters are not AI super-resolution or generative restoration. Actual visual improvement depends on the source, chosen filter values, and device encoder. Processing consumes time, battery, and storage. WhatsApp may recompress media after sharing.

The dedicated Movie Player opens on its own screen and uses libmpv through media_kit for broad local video format support.
